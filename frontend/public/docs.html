01Template ke rules

Template ek normal JSON hota hai jisme values ki jagah {{token}} likha hota hai. Har publish par engine template ko dobara render karta hai. Sirf ye 6 baatein yaad rakhni hain:

1

Token hamesha quotes ke andar rakho. "temp": "{{int:1:9}}" — quotes hatane par template invalid JSON ho jayega aur save hi nahi hoga.

2

Poori value agar ek hi token hai, to real type publish hota hai. "temp": "{{float:1:2:1}}" broker par "temp": 1.4 banta hai — number, string nahi.

3

Token ke saath koi text mila do to string ban jata hai. "fw": "2.4.{{int:0:9}}" → "fw": "2.4.7".

4

Object ki keys me bhi token chalta hai. "{{deviceId}}": { … } — isi tarah payload device ID se keyed banta hai.

5

Galat token chupta nahi. Jo token engine nahi pehchanta wo jaisa ka taisa publish ho jata hai — {{temprature}} message me literally dikhega, isliye typo turant pakda jata hai.

6

JSON na ho to raw text publish hota hai. CSV ya plain value bhi likh sakte ho — tokens tab bhi replace hote hain, bas type conversion nahi hota.

Template
{
  "deviceId": "{{deviceId}}",
  "temperature": "{{walk:18:42:0.4}}",
  "state": "{{oneOf:RUNNING|IDLE|FAULT}}",
  "cycle": "{{counter}}",
  "online": "{{bool:0.95}}",
  "timestamp": "{{iso}}"
}
Broker par publish
{
  "deviceId": "5985623058",
  "temperature": 24.317,
  "state": "RUNNING",
  "cycle": 1,
  "online": true,
  "timestamp": "2026-08-03T10:15:30.123Z"
}

02Numbers & sensors

Ye chaar tokens 90% sensor payloads cover kar dete hain. Farq sirf itna hai ki value kaise badalti hai — jump, drift, ya wave.

{{int:min:max}} alias: {{integer}} number

Matlabmin aur max ke beech ek random poora number, har message par naya.

Do messages ke beech koi rishta nahi — value poore range me kahin bhi kood sakti hai. RSSI, battery %, count jaise fields ke liye theek, temperature jaise smooth sensor ke liye {{walk}} behtar hai.

min
Lower bound (included). Default 0.
max
Upper bound (included). Default 100. Negative bhi chalta hai.
"battery": "{{int:40:100}}"      →   "battery": 87
"rssi": "{{int:-95:-40}}"        →   "rssi": -71
{{float:min:max:decimals}} alias: {{number}} number

Matlabrandom decimal number, jitne decimal places bolo utne.

Wahi behaviour jo {{int}} ka hai, bas rounding aap control karte ho. Power factor, flow rate, pressure jaise readings ke liye.

min
Lower bound. Default 0.
max
Upper bound. Default 100.
decimals
Kitne decimal places. Default 2, allowed 0–10.
"powerFactor": "{{float:0.82:0.99:2}}"   →   "powerFactor": 0.94
"flowLpm": "{{float:0:120:1}}"           →   "flowLpm": 73.4
{{walk:min:max:maxStep}} number

Matlabpichli value yaad rakh ke thoda sa upar-neeche — asli sensor jaisa smooth drift.

Sabse zyada kaam ka token. Har message par value pichli value se ±maxStep ke andar hilti hai aur min/max par clamp ho jati hai — isliye graph jhatke ke bajaye smooth curve banata hai. Pehli value range ke andar random hoti hai. Output 3 decimal tak round hota hai.

min
Value kabhi isse neeche nahi jayegi. Default 0.
max
Value kabhi isse upar nahi jayegi. Default 100.
maxStep
Ek message me zyada se zyada kitna hil sakti hai. Default (max − min) / 20. Chhota step = dheema, realistic drift.
"temperature": "{{walk:18:42:0.4}}"   →   24.317, 24.62, 24.284, 24.51 …

Yaad rakhna state ka: har machine + har field ka apna alag drift chalta hai. Machine Start ya Restart karne par state clear ho jati hai aur value dobara random point se shuru hoti hai.

{{sin:min:max:periodSeconds}} number

Matlabmin–max ke beech ghoomti hui sine wave, fixed time cycle ke saath.

Predictable, repeat hone wala pattern — day/night cycle, motor vibration, heating-cooling loop dikhane ke liye. Value ghadi ke hisaab se chalti hai, message count ke hisaab se nahi, isliye interval badalne par shape wahi rehta hai.

min
Wave ka lowest point. Default 0.
max
Wave ka highest point. Default 100.
periodSeconds
Ek poora cycle kitne second me. Default 60.
"toolTemp": "{{sin:35:85:120}}"   →   2 minute me 35 → 85 → 35 ka smooth cycle

Ye ekmatra number token hai jo Restart par reset nahi hota — wall clock se chalta hai, isliye saari machines ki wave ek hi phase par hoti hai.

03Counters & sequences

Ye tokens run ke dauraan apni jagah yaad rakhte hain — energy meter ka total, cycle count, ya ON/OFF ka fixed pattern.

{{counter}} {{counter:start:step}} alias: {{inc}} number

Matlabhar message par badhta hua number — kabhi peeche nahi jata.

Pehla message start bhejta hai, uske baad har message par step add hota hai. Sequence numbers, kWh totals, uptime seconds ke liye.

start
Pehli value. Default 1.
step
Har message par kitna add ho. Default 1. Decimal (0.5) aur negative (-1) dono chalte hain.
"energyKwh": "{{counter:1000:1}}"   →   1000, 1001, 1002 …
"uptimeSec": "{{counter:0:10}}"     →   0, 10, 20, 30 …

Stop → Start karne par counter wapas start se shuru hoga. Running machine ki config save karne par bhi wo hot-restart hoti hai, to counter reset ho jata hai.

{{seq:A|B|C}} string

Matlablist ki values baari-baari, usi order me, loop me.

Random nahi — bilkul predictable rotation. State machine ya duty cycle test karne ke liye jahan aapko pata hona chahiye ki agla value kya aayega. List khatam hote hi shuru se chalu ho jata hai.

A|B|C
Pipe (|) se alag ki hui values. Repeat karke duration badha sakte ho — ON|ON|OFF matlab 2 message ON, 1 message OFF.
"pump": "{{seq:ON|ON|OFF}}"   →   "ON", "ON", "OFF", "ON", "ON", "OFF" …

Output hamesha string hota hai. {{seq:1|2|3}} se "1" publish hoga, 1 nahi — number chahiye to {{counter}} ya {{range}} use karo.

04Choice & boolean

{{oneOf:A|B|C}} string

Matlablist me se koi ek value, har baar random.

Status, fault code, shift name — jo bhi fixed set me se aata hai. Har option ka chance barabar hota hai; kisi option ko zyada common banana ho to use list me repeat kar do.

A|B|C
Pipe se alag options. Khali list bhejne par "" milta hai.
"state": "{{oneOf:RUNNING|IDLE|FAULT}}"            →   "IDLE"
"faultCode": "{{oneOf:NONE|NONE|NONE|E102|E415}}"  →   60% chance "NONE"

Ye bhi hamesha string deta hai — numbers ke liye {{int}} ya {{range}} chahiye.

{{bool}} {{bool:probability}} boolean

Matlabasli true / false, quotes ke bina.

Online flags, ignition, alarms. Probability set karke aap decide karte ho ki kitni baar true aaye — alarm ko rare rakhna ho to 0.05.

probability
true aane ka chance, 0 se 1. Default 0.5.
"online": "{{bool:0.95}}"   →   "online": true    (95% messages)
"alarm": "{{bool:0.05}}"    →   "alarm": false   (95% messages)

05Time

Har token render hone ke exact moment ka time deta hai. String chahiye ya number — ye choice aapke consumer par depend karti hai.

{{iso}} alias: {{now}} string

MatlabISO-8601 timestamp, UTC me, milliseconds ke saath.

Default choice — har language isko parse kar leti hai aur timezone ka jhagda nahi hota.

"timestamp": "{{iso}}"   →   "2026-08-03T10:15:30.123Z"
{{epoch}} alias: {{timestamp}} number

Matlab1 Jan 1970 se ab tak ke milliseconds, number ke roop me.

JavaScript ka Date.now(). Time-series databases aur charts me seedha chala jata hai.

"ts": "{{epoch}}"   →   "ts": 1785000930123
{{unix}} number

Matlabwahi epoch, par seconds me (milliseconds ke bina).

Purane firmware aur MQTT payload specs aksar seconds expect karte hain.

"ts": "{{unix}}"   →   "ts": 1785000930
{{date}} string

Matlablocal date, YYYY-MM-DD format me.

Server ki local timezone se banta hai (UTC nahi). Human-readable "lastUpdated" fields ke liye.

"day": "{{date}}"   →   "2026-08-03"
{{time}} string

Matlablocal time, HH:MM:SS (24-hour).

Aksar {{date}} ke saath ek hi string me use hota hai.

"lastUpdated": "{{date}} {{time}}"   →   "2026-08-03 15:42:07"

06Identity

Machine ki pehchan. Ek machine ko 50 baar duplicate karne par yahi fields alag hoti hain — template same rehta hai, identity badal jati hai.

{{deviceId}} string

Matlabmachine par set kiya hua device ID — jo asli device apna serial batata.

Payload aur topic dono me isi ko use karna chahiye. Teen formats hain: numeric (10 digits), alphanumeric (12 characters), ya custom (aapka apna, kabhi regenerate nahi hota). Duplicate karne par har copy ko naya device ID milta hai.

"deviceId": "{{deviceId}}"   →   "5985623058"
{{machineId}} string

Matlabsimulator ka internal UUID — machines.json wala id.

Ye API ka identifier hai, device ka nahi. Debugging ke liye theek hai, par device payload me {{deviceId}} zyada sahi lagta hai.

"ref": "{{machineId}}"   →   "d2c5ff1d-1b61-40ea-864f-4db64c2f20ef"
{{machineName}} string

Matlabmachine ka display name jo UI me dikhta hai.

Human-readable label ke liye. Naam me space ya special characters ho sakte hain, isliye topic me daalne se pehle soch lena.

"site": "{{machineName}}"   →   "Airveda"
{{tick}} number

Matlabis run ka kaunsa number message hai — pehla message = 1.

{{counter}} se farq: {{tick}} hamesha 1 se shuru hota hai aur 1-1 karke badhta hai, configure nahi hota. Stop → Start par 1 se dobara.

"seq": "{{tick}}"   →   1, 2, 3, 4 …

07Text & network

{{uuid}} string

Matlabhar message par ek naya random UUID v4.

Message ID / correlation ID ke liye. Ye machine ki pehchan nahi hai — har publish par badal jata hai. Fixed identity chahiye to {{machineId}}.

"msgId": "{{uuid}}"   →   "3f9a02bc-7d41-4e0a-9b2c-88f1d0a6e512"
{{str:length}} alias: {{string}} string

Matlabrandom lowercase letters aur digits, jitni length bolo.

length
Kitne characters. Default 8, allowed 1–256.
"tag": "{{str:6}}"   →   "k4m9x1"
{{hex:length}} string

Matlabrandom hex string (0–9, a–f) — fake checksum ya serial ke liye.

length
Kitne characters. Default 8, allowed 1–256.
"crc": "{{hex:8}}"   →   "3f9a02bc"
{{ip}} string

Matlabrandom private IPv4 address, hamesha 10.x.x.x range me.

Aakhri octet 1–254 rehta hai, to network/broadcast address kabhi nahi banta.

"ip": "{{ip}}"   →   "10.42.7.19"
{{mac}} string

Matlabrandom MAC address, colon-separated lowercase hex.

"mac": "{{mac}}"   →   "a4:1f:0b:9c:2e:7d"
{{lat}} number

Matlabrandom latitude, −90 se +90, 6 decimal places.

Poori duniya me kahin bhi — har message par bilkul alag jagah. Vehicle tracking ke liye {{walk}} se ek chhote area me rakho: "lat": "{{walk:28.40:28.75:0.0008}}".

"lat": "{{lat}}"   →   28.613900
{{lng}} alias: {{lon}} number

Matlabrandom longitude, −180 se +180, 6 decimal places.

"lng": "{{lng}}"   →   77.209000

08Linked values — var aur range

Ye do tokens baaki sab se alag hain: ye naya data nahi banate, balki ek hi generated value ko poore message me share karte hain. Isi se ek battery reading do jagah same aati hai, aur colour apni value se actually match karta hai.

{{var:name:token}} phir kahin bhi: {{var:name}} jo token de

Matlabvalue ek baar banao, naam do, aur message me jitni baar chaho wahi value use karo.

Pehle form me aap value define karte ho — name ke baad jo bhi token likha hai wahi generate hota hai. Doosre form me sirf naam likhne se wahi value dobara mil jati hai. Ek message ke andar dono jagah bilkul same number aata hai.

name
Aapka chuna hua label — batt, aqi, kuch bhi. Sirf usi ek message ke andar valid rehta hai.
token
Koi bhi normal token, poore arguments ke saath — walk:5:100:0.4, int:0:9, wagairah.
"value": "{{var:batt:walk:5:100:0.4}}"   →   50.776
"battery": "{{var:batt}}"                →   50.776   // bilkul wahi value

Order matter nahi karta. Saare {{var:name:token}} sabse pehle evaluate hote hain, isliye {{var:name}} template me upar bhi likh sakte ho — jahan value define hui hai uske pehle bhi. Ek hi naam do baar define kiya to aakhri definition jeetti hai.

{{range:name:limit=out|limit=out|*=out}} string / number

Matlabek {{var}} ki value dekh kar uske hisaab se colour ya label chuno.

Buckets left se right check hote hain aur pehla bucket jeet jata hai jiski limit se value <= hoti hai. * ka matlab "baaki sab" — usse hamesha aakhir me rakho. Agar output dekhne me number hai to number publish hota hai, warna string.

name
Kisi {{var:name:…}} ka naam. Naam galat hua to "" milega.
limit=out
Upper bound aur uska output. Limits chhoti se badi order me likho, warna pehla hi bucket sab kuch kha jayega.
*=out
Fallback — jab kisi limit me fit na ho.
"value": "{{var:aqi:walk:20:220:4}}"
"color": "{{range:aqi:50=#17AF35|100=#74CB40|150=#E1CB43|*=#E14343}}"

aqi = 36    →   "#17AF35"   // 36 <= 50
aqi = 118   →   "#E1CB43"   // 50, 100 fail; 118 <= 150
aqi = 190   →   "#E14343"   // kuch match nahi hua → *

Sirf colours ke liye nahi — *=UNKNOWN ke saath status text, severity level, ya 0/1/2 jaise numeric grades bhi derive kar sakte ho.

09Worked example — Airveda payload

Ye aapki live machines.json wali machine ka template hai, chhota karke. Isme teenon advanced cheezein ek saath hain: token wali object key, readings ka array, aur var + range ki jodi.

Template
{
  "{{deviceId}}": {
    "lastUpdated": "{{date}} {{time}}",
    "data": [
      {
        "type": "aqi",
        "value": "{{var:aqi:walk:20:220:4}}",
        "color": "{{range:aqi:50=#17AF35|100=#74CB40|*=#E14343}}",
        "label": "AQI",
        "unit": ""
      },
      {
        "type": "battery",
        "value": "{{var:batt:walk:5:100:0.4}}",
        "color": "{{range:batt:20=#E14343|50=#E1CB43|*=#17AF35}}",
        "label": "Battery",
        "unit": "%"
      }
    ],
    "battery": "{{var:batt}}"
  }
}

→

10Topic me tokens

Topic bhi ek template hai, bas usme JSON parsing nahi hoti — sab kuch string ban jata hai. Wahi saare tokens chalte hain. 

sensors/{{deviceId}}/telemetry      →   sensors/5985623058/telemetry
factory/line-1/{{deviceId}}/status  →   factory/line-1/5985623058/status
device/airVeda/{{machineId}}        →   device/airVeda/d2c5ff1d-1b61-40ea-…

Payload pehle render hota hai, topic baad me — iska matlab topic me {{var:name}} bhi use kar sakte ho aur usme wahi value aayegi jo abhi message me gayi hai.

Topic me {{machineName}} se bacho agar naam me space ya #/+ ho — ye MQTT wildcards hain aur subscribers ko confuse karte hain. {{deviceId}} hamesha safe characters hi deta hai.

11machines.json ke fields

Har machine isi shape me disk par save hoti hai (backend/data/machines.json) aur isi shape me API leti hai. req matlab create karte waqt zaroori. Limits wahi hain jo backend validate karta hai — cross karne par API 400 deta hai.

Field Type Default Matlab & limits
id string auto Internal UUID, backend banata hai. Templates me {{machineId}} se milta hai. Kabhi khud mat likhna.
name req string — UI me dikhne wala naam. Max 80 characters. Client ID bhi isi se auto-generate hota hai.
description string — Apne liye note — "mobilise local" jaisa. Max 300 characters. Publish kahin nahi hota.
deviceId string auto Device apni jo pehchan batata hai; {{deviceId}} yahi deta hai. Max 64, sirf A–Z a–z 0–9 . _ : - (space allowed nahi).
deviceIdFormat enum numeric numeric = 10 digits · alphanumeric = 12 characters · custom = aapka apna, kabhi regenerate nahi hota.
broker req object — Connection settings — kahan publish karna hai.
broker.url req string — Broker address. Scheme mqtt, mqtts, ws, wss, tcp ya ssl hona chahiye — jaise mqtt://localhost:1883.
broker.username string — Broker auth username. Max 120. Khali chhodo to bina auth connect hoga.
broker.password string — Broker auth password. Max 200. Plain text me file me save hota hai — production credentials yahan mat daalo.
broker.clientId string auto MQTT client ID. Khali chhodo to <name-slug>-<id ke pehle 8> ban jata hai. Do machines ka same client ID = ek dusre ko disconnect karte rahenge.
broker.keepalive number 60 Ping interval seconds me. Allowed 5–3600.
broker.cleanSession boolean true true = broker session yaad nahi rakhta. Simulator ke liye yahi theek hai.
publish req object — Kya bhejna hai aur kitni jaldi-jaldi.
publish.topic req string — MQTT topic; tokens allowed. Max 200 characters.
publish.qos 0 | 1 | 2 0 Delivery guarantee. 0 fire-and-forget (fast, default) · 1 kam se kam ek baar · 2 theek ek baar (sabse dheema).
publish.retain boolean false true par broker aakhri message rakh leta hai aur naye subscriber ko turant de deta hai.
publish.intervalMs req number — Do messages ke beech ka gap, milliseconds me. Allowed 100 – 86,400,000 (24 ghante). 2000 = har 2 second.
publish.payloadTemplate req string — Poora JSON template ek string ke andar — isliye file me \n aur \" escaped dikhte hain. Max 20,000 characters. UI me editing karna aasan hai.
autoStart boolean false true par backend boot hote hi machine apne aap publish karne lagti hai.
createdAt string auto ISO timestamp, backend set karta hai.
updatedAt string auto ISO timestamp, har save par refresh hota hai.

Ek poori machine entry

{
  "id": "d2c5ff1d-1b61-40ea-864f-4db64c2f20ef",
  "name": "Airveda",
  "description": "mobilise local",
  "deviceId": "5985623058",
  "deviceIdFormat": "numeric",
  "broker": {
    "url": "mqtt://localhost:1883",
    "username": "airVeda",
    "password": "Password@123",
    "keepalive": 60,
    "cleanSession": true
  },
  "publish": {
    "topic": "device/airVeda/{{deviceId}}",
    "qos": 0,
    "retain": false,
    "intervalMs": 2000,
    "payloadTemplate": "{\n  \"deviceId\": \"{{deviceId}}\",\n  \"value\": \"{{int:0:100}}\"\n}"
  },
  "autoStart": true,
  "createdAt": "2026-08-03T06:08:42.589Z",
  "updatedAt": "2026-08-03T09:32:55.775Z"
}

12Gotchas — jo baar-baar phansate hain

!

{{oneOf}} aur {{seq}} hamesha string dete hain. "level": "{{oneOf:1|2|3}}" se "level": "2" publish hoga. Number chahiye to {{int}}, {{counter}} ya {{range}} use karo — {{range}} numeric output ko apne aap number bana deta hai.

!

Start / Restart par sab reset ho jata hai. walk, counter, seq aur tick — sab shuru se. Running machine ki config save karne par wo hot-restart hoti hai, to wahan bhi counters zero se chalte hain. Sirf {{sin}} ghadi se chalta hai, isliye wo reset nahi hota.

!

{{range}} ki buckets chhoti se badi order me. *=… hamesha aakhir me. Ulta likha to pehla bucket sab values kha jayega aur colour kabhi badlega hi nahi.

!

{{var:name}} ka naam galat hua to "" milta hai — error nahi aata. Field khali dikhe to sabse pehle spelling check karo.

!

Duplicate karne par identity badalti hai, template nahi. Har copy ko naya machineId, naya deviceId aur apna client ID milta hai — broker, topic aur payload template same rehte hain. Isiliye topic me {{deviceId}} likhna zaroori hai, warna 50 copies ek hi topic par publish karengi.

!

intervalMs minimum 100 hai. Isse tez chahiye to ek hi machine ko duplicate karke chala lo — 10 machines @ 100 ms = 100 messages/second.

!

Save karne se pehle Preview dabao. Preview asli render chalata hai par counters ko aage nahi badhata — invalid JSON ya galat token wahin pakda jata hai.
